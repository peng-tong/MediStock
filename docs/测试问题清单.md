# MediStock 测试问题清单

> 逐页功能测试记录。状态：**待修复** / **已修复** / **复测通过**。

## 1. 5 个列表接口返回裸数组，前端期望分页对象（严重）
- 页面：`/base/categories`、`/base/suppliers`、`/base/customers`、`/base/warehouses`、`/system/roles`
- 现象：新增数据提示"保存成功"且已入库，但列表始终显示"暂无数据"，编辑/删除无法操作
- 原因：后端 `GET /api/drug-categories`、`/api/suppliers`、`/api/customers`、`/api/warehouses`、`/api/roles` 返回裸数组 `Result<List<...>>`，而前端 `getCategories/getSuppliers/getCustomers/getWarehouses/getRoles` 期望 `{list,total}` 分页结构
- 对照：`/api/drugs`、采购/销售/库存/用户/租户接口均为分页结构，正常
- 备注：`/api/menus` 也是数组，但前端按树数组处理，正常
- 状态：**已修复**（后端 5 个 Controller 改为返回 `PageResult`，需复测）

## 2. 采购入库页多状态筛选参数报 400（严重）
- 页面：`/purchase/inbound` 采购入库
- 现象：列表接口 `GET /api/purchases/orders?status=1,2` 抛 `MethodArgumentTypeMismatchException`（`status` 参数为 Integer 无法解析 "1,2"），页面回退 mock 数据
- 原因：前端 `PurchaseInbound.vue` 传逗号分隔多状态，后端 `PurchaseOrderController.page` 的 `status` 为 `Integer`
- 状态：**已修复**（后端 `status` 改 String 并支持逗号分隔多值 `in()` 查询，需复测）

## 3. 超管登录新建单据返回 500「系统内部错误」（严重）
- 页面：`/purchase/orders` 新建采购单（采购入库、销售开单、退货、盘点同样受影响）
- 现象：`POST /api/purchases/orders` 返回 500；后端日志 `SQLITE_CONSTRAINT_NOTNULL ... purchase_order.tenant_id`
- 原因：`MybatisPlusConfig` 中 `TenantLineInnerInterceptor` 在超管（tenantId=0）时 `ignoreTable()` 返回 true，**不会自动注入 tenant_id**，而 `purchase_order` / 明细 / `inv_stock` / `inv_flow` / 销售与退货单据 / 盘点单等表的 `tenant_id` 均为 `NOT NULL`
- 修复：所有单据/库存 insert 显式补默认租户：
  `entity.setTenantId(TenantContext.getTenantId() == null ? 0L : TenantContext.getTenantId())`
  涉及 `PurchaseOrderService`、`SalesOrderService`、`SalesReturnService`、`PurchaseReturnService`、`StockService`（stock/batch/flow）、`StocktakeService`（头+明细）
- 状态：**已修复**，接口层已验证：采购单创建、采购入库、销售单创建/出库、销售退货、采购退货、盘点创建均返回 `code=0`

## 4. 盘点明细表 actual_quantity 被建成 NOT NULL（严重，历史库问题）
- 页面：`/inventory/stocktake` 新建盘点单
- 现象：`POST /api/inventory/stocktakes` 返回 500，日志 `NOT NULL constraint failed: inv_stocktake_item.actual_quantity`
- 原因：`schema.sql` 中该列可空（未录入实盘即为 null，确认前由服务层校验），但本地既有库是在该列仍为 NOT NULL 时创建的；`CREATE TABLE IF NOT EXISTS` 不会修正既有表结构
- 修复：重建本地库 `inv_stocktake_item` 表（列定义与 `schema.sql` 一致，数据为空可安全迁移）
- 状态：**已修复**，接口层已验证盘点创建成功

## 5. 前后端接口契约不匹配（严重，批量）
- 页面：采购订单、采购退货、销售开单、销售退货、库存盘点、用户管理、租户管理
- 现象：新建单据返回 `{"code":400,"message":"order 不能为null"}`；状态/密码等参数后端收不到或 400
- 原因：后端部分接口为「头+明细」包装对象（`{order,items}`、`{purchaseReturn,items}`、`{salesReturn,items}`）、部分参数走 query string（`warehouseId`、`actualQuantity`、状态、密码、角色/菜单 id 数组），前端按扁平 body / JSON 字段传
- 修复：统一在 `frontend/src/api/purchase.js`、`sales.js`、`inventory.js`、`system.js` 做契约适配（包装对象、query 参数），不改后端接口形态
- 状态：**已修复**，接口层已验证采购/销售/退货/盘点/用户/租户相关调用返回 `code=0`

## 26. 新建销售单的「选择批号」下拉是假数据

- 现象：批号下拉是前端写死的 3 条静态批次（A20250812 / B20250903 / L20251002），与实际库存无关，也未按所选药品过滤；有效期列同样取这份假数据
- 核实：后端销售单明细无 `batchNo` 字段，出库由 `SalesOrderService.outbound` 按效期优先 FIFO 自动扣批次，所选批号不会生效
- 处理：**移除批号选择与假数据**，改为「可出库批次（效期优先）」只读展示——选中药品/仓库后调用 `GET /api/inventory/stocks/batches` 拉真实批次（过滤零库存与过期，按有效期升序）；仓库变更时刷新全部行；无库存显示「无可用批次」
- 状态：**已修复**，接口核对 drugId=2 批次 `A20260229 / 2027-03-26 / 10 盒 / 一号常温仓`；浏览器验证显示与该数据一致，切换药品变为「无可用批次」

## 27. 销售出库始终报「单据状态不允许该操作」
- 页面：销售管理 → 销售开单 → 出库
- 现象：任何单据点「出库」都提示单据状态不允许该操作
- 根因：`SalesOutboundService.outbound` 只允许 `status == 0`（草稿）出库，但前端流程要求先「提交」→ 1（待出库）后才出现出库按钮，前后端状态机不一致，导致出库永远失败
- 处理：后端校验改为 `status == 1`（待出库）才可出库，草稿必须先提交；前端出库按钮只对状态 1 显示（原来还错误包含不存在的状态 2）
- 状态：**已修复**，接口验证 草稿出库→1007；提交后出库→成功、状态 3、批次库存 5→3；超库存单据出库→1008「库存不足」且状态不变；浏览器验证「出库成功，已按效期优先 FIFO 扣减批次」并变为「已出库」

## 28. 销售单保存不校验库存 / 折扣系数计算错误
- 现象 1：明细数量大于库存仍能保存成功
- 说明：库存（含过期批次过滤、负库存）校验只在**出库扣减**时做（`StockService.outboundFifo`），保存/提交阶段按草稿业务语义不强制校验库存
- 处理 1：前端明细行展示「可用库存 N 盒」，超量时红字提示「已超出，出库时将被拦截」，保存仍允许，出库时后端拦截并返回「库存不足」
- 现象 2（顺带发现）：折扣默认值 1 被 `discountFactor` 按百分比解释为 1%，导致应收金额只剩 1%、优惠金额虚高
- 处理 2：`discountFactor` 改为 `>1` 才按百分比换算，`1` 表示无折扣（[SalesOrder.vue](file:///d:/Workplace/ai/MediStock/frontend/src/views/sales/SalesOrder.vue#L245-L250)）
- 状态：**已修复**
